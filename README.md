# LifeRPG

Консольная версия LifeRPG для отслеживания привычек и развития персонажа.

## Запуск

Команды PowerShell из корня репозитория, Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe main.py --demo-pr01
```

Первый запуск открывает меню. Можно просматривать каталог, искать по названию,
фильтровать по категории, регистрировать активность по коду и смотреть прогресс,
историю и сводку. В демонстрации ПР1 ввод `350` даёт Силе уровень 3 и 125/150 XP.

## Начисление и сохранение

Открой меню командой `py -3.12 main.py`. Выбери `2`, введи
`meditation` и нажми Enter для обычной интенсивности. Повтори один раз.
Если оба выполнения пришлись на один игровой день, Воля достигнет
уровня 2 с 0/125 XP. Выйди через `0`, снова запусти приложение и выбери
`3`. Через `1` можно найти «Медитацию» и увидеть два выполнения и
следующий множитель ×0,6. Игровой день меняется в 04:00 по времени ОС.

Прогресс хранится в `data/events.jsonl`. Для отдельного журнала используй
`--state путь.jsonl`. Для копии укажи новый файл, например:

```powershell
py -3.12 main.py --backup data/events.jsonl.bak
```

Если журнал повреждён, программа укажет файл и строку. Исходный журнал
можно скопировать через `--backup`, включая прерванную последнюю запись.

При первом обычном запуске старый `data/state.json` переносится в журнал
одним снимком истории и прогресса. У прежних записей нет дат, поэтому
они сохраняют XP и историю, а счётчик повторов начинается с датированных
выполнений. Исходный JSON сохраняется. Прежнее меню с исправлением и отменой
можно открыть командой `py -3.12 main.py --state data/state.json`.
Правки в этом режиме относятся к выбранному JSON.

Порог перехода с уровня 1 равен 100 XP, с уровня 2 — 125 XP, с уровня 3 —
150 XP. При открытии журнала обновление записывается событием `rules.updated`.
Действующий прогресс пересчитывается из сохранённых начислений по новым
порогам. Пункты 5 и 6 исправляют или отменяют датированные выполнения
по номеру из истории. Старые строки остаются в журнале. Последующие
исторические начисления сохраняют свои суммы, а счётчики учитывают
действующие выполнения. Удаление начисления может снять уровень.
Импортированные записи JSON v1 по-прежнему доступны в исходном JSON.

XP округляется вниз до целого после применения всех коэффициентов.
При положительном базовом XP начисляется минимум 1 XP, при нулевом — 0.
С пятого выполнения применяется ×0,15, включая все последующие.

## Базовые навыки и режим разработчика

Пункт 11 показывает уровень, XP и статус Писательства. В пункте 2 выбери
`writing` («Работа над текстом») и подтверди интенсивность. Выполнение даёт
50 XP навыка. После перезапуска пункт 11 покажет записанный прогресс.

Порог следующего уровня базового навыка равен текущему уровню × 1 000 XP.
На уровне 15 остаток идёт к мастерству. Статус присваивается один раз при
15 000 XP на этом уровне. Дальнейший опыт накапливается на уровне 15.
Писательство состоит из одного базового навыка. Старые события поднавыков
сохраняются в журнале и не участвуют в новых начислениях.

Пункт 9 показывает перки, их эффекты и состояния. Перки включены по
умолчанию. «Победа над собой» открывается после замены «Ленивого».
Для настройки выбери пункт 12, введи код перка и выбери 1 или 0.
Введи 0 вместо кода, чтобы выйти из режима разработчика. Настройка
сохраняется в журнале сразу. При новом запуске режим выключен.

Для проверки выключи `lazy`, выйди из режима, перезапусти приложение
и выполни `meditation`. Первое обычное выполнение даст 50 XP Воли
вместо 75 при включённом «Ленивом».

## Достижения, статистика и диагностика

Пункт 13 показывает каталог достижений. Две обычные медитации на новом
сохранении с включённым «Ленивым» повышают Волю до второго уровня и открывают
«Путь в тысячи ли». Пункт 14 строит отчёт по игровым датам включительно.
Пустые даты означают весь журнал. В отчёте отдельно видны начисления,
списания и погашение долга. Данные направлений пока выводятся по
характеристикам; веса, агрегация и метрика «Социальность» остаются TBD.

В пункте 12 команды 1–4 выполняют партию активностей, меняют длину серии,
устанавливают уровень или выдают достижение. Код `player` задаёт общий
уровень вручную. Порог автоматического общего уровня остаётся TBD.
Партия фиксирует выполнения по одному и сообщает, сколько уже записано.

Автоматическое затухание отключено до согласования первого дня списания,
порядка на границе суток, округления и предела долга. Движок списания и
погашения проверяется на отдельном журнале с явной тестовой политикой.
Для проверки этого сценария запусти `python -m pytest -k rust_policy`.

Для этапа 13 консоль использует `liferpg.game.complete` с UUID операции.
Чтение выполняется через `liferpg.journal.read_events`, состояние строится
`liferpg.game.project`, отчёт — `liferpg.statistics.period_statistics`.
При чтении живого журнала захватывай `journal_lock`. Повреждённая строка
блокирует запись; сначала сделай резервную копию. После проверки удали
только подтверждённый неполный хвост из рабочей копии и повтори запуск.

## Структура

| Файл | Ответственность |
|---|---|
| `main.py` | Точка входа, передаёт управление консольному интерфейсу |
| `liferpg/cli.py` | Аргументы, меню, ввод и вывод |
| `liferpg/application.py` | Регистрация, исправление, отмена и вызов сохранения |
| `liferpg/domain/progression.py` | Формула порога, начисление и формат прогресса из ПР1 |
| `liferpg/domain/character.py` | Персонаж и характеристики из ПР3 |
| `liferpg/domain/activities.py` | Каталог, снимки XP и история из ПР3 |
| `liferpg/game.py` и `liferpg/journal.py` | Начисление, восстановление и запись журнала |
| `liferpg/storage.py` | Проверка, загрузка и сохранение JSON v1 |
| `tests/` | Проверки ядра, операций приложения, хранилища и CLI |

Игровое ядро доступно для прямого вызова из Python. Операции приложения
принимают функцию сохранения, поэтому их можно проверить без ввода и файла.

## Проверка и отладка

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 . --extend-exclude=.venv,venv
```

Поставь точку останова в `Attribute.award_xp`. После двух регистраций
`training` открой характеристики и пошагово пройди второй вызов для Силы.
Наблюдай `amount`, `self._level` и `self._current_xp`. Они показывают переход
с уровня 1 и 50 XP на уровень 2 и 0 XP. После исправления повтори проверку.
В `load_log` можно проследить, как код активности становится ссылкой на объект.
